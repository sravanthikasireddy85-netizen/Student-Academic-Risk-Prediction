# Student Academic Risk Prediction & Early Warning System

A local Streamlit application for exploring academic risk indicators, comparing classification models, recording predictions in SQLite, and creating supportive recommendations.

> **Important:** The bundled training data is synthetic/demo data. The model is not validated for real student populations. Do not use predictions as the sole basis for academic decisions.

## Features
- Student risk prediction: Low, Medium, or High.
- Model-estimated class probabilities, labelled as estimates.
- Human-readable risk flags and personalized supportive recommendations.
- SQLite student records and prediction history.
- Early-warning filtering and downloadable CSV.
- CSV upload, validation, batch prediction, and results download.
- Model comparison: Logistic Regression, Decision Tree, Random Forest, Extra Trees, and XGBoost when installed and compatible.
- Accuracy, weighted precision/recall/F1, confusion matrix, classification report, and feature importance where supported.
- Synthetic sample dataset generator; no API key or paid service required.

## Installation (Windows)
1. Install Python 3.10 or newer.
2. Extract the ZIP and open a terminal in the project folder.
3. Recommended: create a virtual environment:
   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```
4. Install dependencies:
   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
5. Train models and create the labelled synthetic CSV:
   ```powershell
   python -m src.train_model
   ```
6. Run the app:
   ```powershell
   streamlit run app.py
   ```
   Streamlit prints a local URL, usually `http://localhost:8501`.

On first app launch, if no trained model exists, the app attempts to train one automatically. XGBoost is included in requirements but the training script gracefully skips it if it cannot import or train; other models remain available.

## How to use
1. Open **Student Prediction**, enter values, and click **PREDICT ACADEMIC RISK**.
2. Review estimated risk probabilities, contextual risk flags, and recommendations.
3. Click **Save Prediction** to store the student and prediction history in local SQLite.
4. Review **Dashboard**, **Student Records**, and **Early Warning System**.
5. In **Data Upload**, upload a CSV with the feature columns listed on the page. The CSV must also include `student_id` and `student_name`.
6. Use **Model Performance** to compare models and inspect the selected model's confusion matrix/report.

## Input columns
`student_id`, `student_name`, `age`, `gender`, `attendance_pct`, `previous_gpa`, `internal_marks_pct`, `assignment_completion_pct`, `backlogs`, `study_hours_per_day`, `previous_failures`, `class_participation_pct`, `assignment_submission_rate`, `number_of_subjects`, `previous_semester_pct`.

## Dataset and target
The training script creates 600 synthetic records and writes `data/raw/synthetic_students.csv`. The target `academic_risk` is derived from an illustrative weighted combination of attendance, GPA, marks, assignment completion, backlogs, study time, and failure history, with random noise. This introduces a known limitation: the model learns an artificial label-generating process rather than real student outcomes. It must not be presented as a validated predictor of failure or dropout.

## Algorithms and evaluation
The pipeline compares Logistic Regression, Decision Tree, Random Forest, Extra Trees, and XGBoost when available. Data is split with stratification into training and held-out test sets. Preprocessing imputes missing values, scales numeric values, and one-hot encodes gender. The best model is selected by weighted F1, then weighted recall and precision as tie-breakers—not accuracy alone. Metrics in `models/model_metadata.json` are generated on synthetic data and should be interpreted only as a software demonstration.

## Tests

Tests cover input range checks, required fields, recommendation generation, and SQLite record/prediction CRUD. Run tests after installing requirements. Tests create a local SQLite database under `data/`.

## Ethical considerations and limitations
- Use anonymized data and restrict access to student records.
- Do not use sensitive personal characteristics to punish students or deny opportunities.
- Explain uncertainty and allow teacher review and student context.
- Rules shown as contributing flags are readable indicators, not causal attributions or SHAP explanations.
- No external API, cloud service, or API key is required.
- Production use requires representative data, leakage review, calibration, external validation, fairness audits, security/access controls, and human oversight.
